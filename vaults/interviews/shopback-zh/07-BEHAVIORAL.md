# 第四轮：文化与行为面试

> 1 小时，Google Meet。本轮评估文化契合度、协作能力和领导力。

## ShopBack 核心价值观

基于他们的文化和工程实践：

1. **客户至上** - 用户和商家放在第一位
2. **快速行动，保持敏捷** - 虽有规模但保持创业心态
3. **跨越边界协作** - BREW 文化，跨团队工作
4. **对结果负责** - 端到端的主人翁意识
5. **数据驱动** - 衡量一切，频繁实验

---

## STAR 框架

每个回答都按以下结构组织：

| 要素         | 内容                 | 时长          |
| ------------ | -------------------- | ------------- |
| **S**（情境）| 背景和上下文         | 15-20 秒      |
| **T**（任务）| 你的具体职责         | 10-15 秒      |
| **A**（行动）| 你做了什么（重点）   | 60-90 秒      |
| **R**（结果）| 可量化的成果         | 15-20 秒      |

---

## 可能的问题与准备

### 类别一：技术领导力

**问：讲一个你设计的需要大规模扩展的系统。**

准备：想一个你构建的增长了 5-10 倍的系统。涵盖：

- 初始设计决策和约束
- 如何预判扩展需求
- 你做出的权衡（一致性 vs 可用性，成本 vs 性能）
- 监控以及如何发现瓶颈
- 结果：性能指标、成本节省、可靠性提升

**问：描述一次你在信息不完整的情况下做出困难技术决策的经历。**

准备：选一次你在缺乏明确数据的情况下在技术/方案之间做选择。涵盖：

- 缺少什么信息以及为什么
- 如何评估选项（原型、基准测试、团队意见）
- 你做出的决定及其理由
- 结果如何，以及你会有什么不同做法

**问：讲一次你处理的生产事故。**

准备：选一次真实的宕机或性能下降。涵盖：

- 如何发现问题
- 你的即时响应（分类、沟通）
- 根因分析过程
- 修复实施和验证
- 事后复盘和预防措施

---

### 类别二：协作

**问：讲一次你与跨职能团队合作的经历。**

准备：ShopBack 重视跨团队协作（BREW）。想想与以下角色合作的经历：

- 产品经理进行功能优先级排序
- 数据科学家开发推荐算法
- 前端/移动团队协商 API 接口
- DevOps 进行基础设施决策

**问：描述一次你与同事在技术方案上的分歧。你是如何解决的？**

准备：展示你能够：

- 真诚倾听对方的观点
- 用数据/证据支持你的立场
- 在适当时寻找妥协或让步
- 不论结果如何都维护好关系

**问：你如何指导或帮助初级开发者成长？**

准备：举例说明：

- 代码评审中教导性而非纠正性的反馈
- 结对编程或知识分享
- 创建文档或指南
- 委派有挑战性的工作以提升他人技能

---

### 类别三：问题解决

**问：讲一次你显著提升系统性能的经历。**

准备：量化改进。涵盖：

- 如何识别瓶颈（性能分析、监控）
- 根因分析
- 实施的解决方案（缓存、查询优化、架构变更）
- 前后指标对比（延迟、吞吐量、成本）

**问：描述一个需求在中途大幅变更的项目。**

准备：展示适应能力：

- 原始计划和进度
- 什么变了以及为什么
- 你如何调整（重新排优先级、范围协商）
- 尽管有变化你最终交付了什么

**问：讲一次你跨多个服务调试复杂问题的经历。**

准备：与 ShopBack 的微服务架构相关：

- 你如何跨服务追踪问题
- 使用的工具和技术（分布式追踪、日志关联）
- 你如何与其他团队协调
- 解决方案和预防措施

### 类别四：文化契合

**问：为什么选择 ShopBack？**

好的回答应该包括：

- 对他们返现/奖励模式的真正兴趣
- 对他们工程挑战的热情（规模、多市场）
- 与他们技术栈的契合（Node.js/TypeScript）
- 对亚太市场和增长轨迹的兴趣
- 你研究过的具体内容（BREW 文化、多租户迁移）

**问：你理想中的工程文化是什么样的？**

与 ShopBack 价值观对齐：

- 自主权与协作的平衡
- 数据驱动的决策
- 快速迭代并有质量保障
- 跨团队学习和知识共享

**问：你对未来 2-3 年有什么规划？**

展示与 ShopBack 一致的成长志向：

- 深化分布式系统专业知识
- 领导技术计划（如他们的 BREW 项目）
- 指导团队成员
- 参与平台/架构决策

### 类别五：ShopBack 特定问题

**问：你会如何为 13 个不同市场构建一个功能？**

讨论：

- 配置驱动 vs 代码驱动的市场差异
- 功能开关实现渐进发布
- 本地化（货币、语言、法规）
- 测试策略（市场特定的边界情况）
- 按市场监控健康状况

**问：你如何处理跨时区工作？**

ShopBack 有团队在新加坡、越南、台湾、深圳：

- 异步沟通（清晰的文档、PR 作为沟通手段）
- 关键讨论利用时间重叠窗口
- 时区感知的部署排期
- 书面决策优于口头决策

**问：你如何平衡交付速度与代码质量？**

- 根据上下文明确"足够好"的定义
- 自动化质量关卡（CI/CD、代码检查、测试）
- 代码评审作为质量保证机制
- 技术债务追踪和定期偿还
- 区分原型代码和生产代码

## 向面试官提的问题

- "一个典型的 BREW 项目是什么样的？团队如何组建？"
- "多租户迁移进展如何？最大的挑战是什么？"
- "你们团队的 On-call 轮值是怎样的？"

### 关于工程文化

- "你们如何平衡新功能开发和技术债务偿还？"
- "你们的部署频率如何？团队多久发布一次？"
- "你们如何处理线上事故？事后复盘流程是怎样的？"

### 关于成长

- "高级工程师在这里的职业发展路径是什么？"
- "有没有机会参与不同市场或产品的工作？"
- "团队当前面临的最大技术挑战是什么？"

### 关于岗位

- "我的前 90 天会是什么样的？"
- "我会加入哪个团队？他们当前的优先事项是什么？"
- "这个岗位第一年的成功标准是什么？"

## 常见错误提醒

1. **太笼统** - 使用有具体数据和成果的案例
2. **说前任雇主坏话** - 将挑战描述为学习机会
3. **不提问** - 准备至少 3-4 个深思熟虑的问题
4. **独白式回答** - 每个回答控制在 2-3 分钟以内
5. **对约束持消极态度** - 展示你能在限制条件下高效工作
6. **缺乏好奇心** - 对他们的挑战提出后续问题
