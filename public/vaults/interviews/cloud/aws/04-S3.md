# Amazon S3 (Simple Storage Service)

S3 is AWS's object storage service. It is not a filesystem -- there are no directories, no file locks, no append operations. You store **objects** (files + metadata) in **buckets** (globally unique namespaces), and each object is identified by a **key** (a string that looks like a path but is flat). S3 offers 11 nines (99.999999999%) of durability, scales to exabytes, and serves as the backbone for data lakes, static hosting, backups, and log archives across AWS.

---

## Core Concepts

### Buckets

- Globally unique name (across all AWS accounts)
- Created in a specific AWS Region -- data stays in that Region unless you replicate it
- Flat namespace internally; the `/` in keys is a convention, not a directory separator
- Soft limit of 100 buckets per account (can be raised to 1000)

### Objects

- An object = key + value (data) + metadata + version ID
- Max object size: **5 TB**
- Max single PUT: **5 GB** (use multipart upload for anything larger)
- Metadata: system metadata (Content-Type, Last-Modified) + user-defined (x-amz-meta-\*)

### Keys and Prefixes

```
s3://my-bucket/logs/2024/01/15/app.log
               ^^^^^^^^^^^^^^^^^^^^^^^^^
               This entire string is the key

s3://my-bucket/logs/2024/01/
               ^^^^^^^^^^^^^
               This is a "prefix" (not a folder)
```

The S3 console displays prefixes as folders, but there is no directory hierarchy. This matters when you think about performance -- S3 partitions by key prefix.

## Storage Classes

| Class                          | Use Case                                      | Retrieval   | Min Duration | Cost Rank               |
| ------------------------------ | --------------------------------------------- | ----------- | ------------ | ----------------------- |
| **Standard**                   | Frequently accessed data                      | Instant     | None         | $$$$$                   |
| **Intelligent-Tiering**        | Unknown/changing access patterns              | Instant     | 30 days      | $$$$ (+ monitoring fee) |
| **Standard-IA**                | Infrequently accessed, rapid retrieval needed | Instant     | 30 days      | $$$                     |
| **One Zone-IA**                | Infrequent, non-critical, reproducible data   | Instant     | 30 days      | $$                      |
| **Glacier Instant Retrieval**  | Archive, but need ms retrieval                | Instant     | 90 days      | $$                      |
| **Glacier Flexible Retrieval** | Archive, retrieval in minutes to hours        | 1-12 hours  | 90 days      | $                       |
| **Glacier Deep Archive**       | Long-term compliance archives                 | 12-48 hours | 180 days     | $ (cheapest)            |

**Rule of thumb:** Start with Standard. Use Intelligent-Tiering if you cannot predict access patterns. Use lifecycle policies to move data to cheaper tiers over time.

## Versioning

Versioning keeps every version of every object. Once enabled on a bucket, it cannot be fully disabled -- only suspended.

```bash
# Enable versioning
aws s3api put-bucket-versioning \
  --bucket my-bucket \
  --versioning-configuration Status=Enabled

# List object versions
aws s3api list-object-versions --bucket my-bucket --prefix config.json
```

Key behaviors:

- Deleting a versioned object adds a **delete marker** (the object is not actually removed)
- To permanently delete, you must specify the version ID
- Versioning + lifecycle policies = cost-effective backup strategy
- MFA Delete adds an extra layer of protection against accidental deletes

## Lifecycle Policies

Automate transitions between storage classes and expiration of objects.

```json
{
  "Rules": [
    {
      "ID": "ArchiveOldLogs",
      "Filter": { "Prefix": "logs/" },
      "Status": "Enabled",
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" }
      ],
      "Expiration": { "Days": 365 },
      "NoncurrentVersionExpiration": { "NoncurrentDays": 30 }
    }
  ]
}
```

```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-bucket \
  --lifecycle-configuration file://lifecycle.json
```

## Encryption

### Server-Side Encryption Options

| Method               | Key Management                                 | Use Case                                   |
| -------------------- | ---------------------------------------------- | ------------------------------------------ |
| **SSE-S3** (AES-256) | AWS manages keys entirely                      | Default, simplest option                   |
| **SSE-KMS**          | AWS KMS manages keys, you control key policies | Audit trail via CloudTrail, key rotation   |
| **SSE-C**            | You provide the key with every request         | Full key control, AWS never stores the key |

Since January 2023, all new objects are encrypted with SSE-S3 by default.

```bash
# Upload with SSE-KMS
aws s3 cp file.txt s3://my-bucket/ \
  --sse aws:kms \
  --sse-kms-key-id alias/my-key
```

## Access Control

### Order of Preference (Modern)

1. **Bucket policies** -- JSON-based, attached to the bucket. Use for cross-account access, public access, IP restrictions.
2. **IAM policies** -- Attached to users/roles. Use for controlling what your own principals can do.
3. **S3 Access Points** -- Simplified per-application access control for shared data lakes.

**ACLs are legacy.** AWS recommends disabling them entirely with S3 Object Ownership set to "Bucket owner enforced."

### Example Bucket Policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontOAC",
      "Effect": "Allow",
      "Principal": { "Service": "cloudfront.amazonaws.com" },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::123456789012:distribution/EXXXXX"
        }
      }
    }
  ]
}
```

```bash
aws s3api put-bucket-policy --bucket my-bucket --policy file://policy.json

# Block all public access (recommended default)
aws s3api put-public-access-block --bucket my-bucket \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

## Pre-Signed URLs

Generate temporary URLs that grant time-limited access to private objects without changing bucket policies.

```bash
# Generate a pre-signed URL valid for 1 hour (3600 seconds)
aws s3 presign s3://my-bucket/reports/q4.pdf --expires-in 3600

# Output: https://my-bucket.s3.amazonaws.com/reports/q4.pdf?X-Amz-Algorithm=...&X-Amz-Expires=3600&...
```

Use cases: download links in emails, temporary upload URLs for client-side uploads, sharing files without making them public.

## Event Notifications

S3 can emit events on object creation, deletion, and other operations.

| Target          | Use Case                                            |
| --------------- | --------------------------------------------------- |
| **Lambda**      | Image thumbnail generation, ETL trigger             |
| **SQS**         | Buffered processing, decoupled consumers            |
| **SNS**         | Fan-out to multiple subscribers                     |
| **EventBridge** | Advanced filtering, routing, cross-account delivery |

**EventBridge is the modern choice.** It supports filtering by object key, size, metadata, and routing to 20+ AWS service targets.

```bash
# Enable EventBridge notifications for a bucket
aws s3api put-bucket-notification-configuration --bucket my-bucket \
  --notification-configuration '{"EventBridgeConfiguration": {}}'
```

## Cross-Region Replication (CRR)

Asynchronously replicates objects to a bucket in another Region.

Requirements:

- Versioning must be enabled on both source and destination buckets
- IAM role with permission to replicate
- Can replicate to a different AWS account

Use cases: disaster recovery, compliance (data residency), lower-latency reads.

```bash
aws s3api put-bucket-replication --bucket source-bucket \
  --replication-configuration file://replication.json
```

There is also **Same-Region Replication (SRR)** for log aggregation and live replication between accounts in the same Region.

## S3 Transfer Acceleration

Uses CloudFront edge locations to accelerate uploads over long distances. Useful when uploading from geographically distant clients.

```bash
# Enable Transfer Acceleration
aws s3api put-bucket-accelerate-configuration \
  --bucket my-bucket \
  --accelerate-configuration Status=Enabled

# Upload using accelerated endpoint
aws s3 cp large-file.zip s3://my-bucket/ --endpoint-url https://my-bucket.s3-accelerate.amazonaws.com
```

## Static Website Hosting

S3 can serve static websites directly (HTML, CSS, JS).

```bash
# Enable static website hosting
aws s3 website s3://my-bucket/ --index-document index.html --error-document error.html

# Endpoint format: http://my-bucket.s3-website-us-east-1.amazonaws.com
```

For production, put **CloudFront** in front of the S3 website for HTTPS, caching, and custom domain support.

## Performance Optimization

### Multipart Upload

Required for objects > 5 GB, recommended for objects > 100 MB.

```bash
# AWS CLI handles multipart automatically for large files
aws s3 cp large-file.tar.gz s3://my-bucket/ --expected-size 10737418240

# Configure multipart threshold and chunk size
aws configure set default.s3.multipart_threshold 64MB
aws configure set default.s3.multipart_chunksize 16MB
```

### Byte-Range Fetches

Download only a portion of an object. Useful for large files where you only need a header or specific byte range.

### S3 Select / Glacier Select

Run SQL expressions directly against CSV, JSON, or Parquet objects without downloading the full object.

```bash
aws s3api select-object-content \
  --bucket my-bucket --key data.csv \
  --expression "SELECT s.name, s.age FROM s3object s WHERE s.age > 30" \
  --expression-type SQL \
  --input-serialization '{"CSV": {"FileHeaderInfo": "USE"}}' \
  --output-serialization '{"CSV": {}}' output.csv
```

### Throughput Limits

- **3,500 PUT/COPY/POST/DELETE** requests per second per prefix
- **5,500 GET/HEAD** requests per second per prefix
- Spread keys across prefixes to parallelize throughput

## Common CLI Commands

```bash
# List buckets
aws s3 ls

# List objects in a bucket with a prefix
aws s3 ls s3://my-bucket/logs/ --recursive --human-readable --summarize

# Copy a file to S3
aws s3 cp ./backup.sql s3://my-bucket/backups/

# Sync a local directory to S3 (only uploads changed files)
aws s3 sync ./dist/ s3://my-bucket/ --delete

# Download a file
aws s3 cp s3://my-bucket/config.json ./config.json

# Remove an object
aws s3 rm s3://my-bucket/old-file.txt

# Remove a bucket (must be empty)
aws s3 rb s3://my-bucket

# Force remove a bucket and all contents
aws s3 rb s3://my-bucket --force

# Copy between buckets
aws s3 sync s3://source-bucket/ s3://dest-bucket/

# Set bucket policy
aws s3api put-bucket-policy --bucket my-bucket --policy file://policy.json

# Get bucket policy
aws s3api get-bucket-policy --bucket my-bucket
```

## Common Gotchas

| Gotcha                                 | Detail                                                                                                                                                                                        |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Eventual consistency (mostly gone)** | Since December 2020, S3 provides strong read-after-write consistency for all operations. But understand the history -- older docs and interview questions may reference eventual consistency. |
| **5 TB object limit**                  | Single object max is 5 TB. Plan your data partitioning.                                                                                                                                       |
| **5 GB single PUT limit**              | Use multipart upload for anything larger. The CLI handles this automatically.                                                                                                                 |
| **Bucket names are globally unique**   | Across all AWS accounts worldwide. Good names are taken.                                                                                                                                      |
| **3,500 PUT/s per prefix**             | Spread writes across prefixes if you need higher throughput. Add randomized prefix (e.g., hex hash) for high-throughput workloads.                                                            |
| **Deletion is not instant**            | Versioned buckets accumulate delete markers and old versions. Clean up with lifecycle policies.                                                                                               |
| **No rename operation**                | "Rename" is copy + delete. Expensive for large objects.                                                                                                                                       |
| **Requester Pays**                     | If enabled, the requester (not the bucket owner) pays for data transfer. Cross-account access patterns can surprise you with costs.                                                           |
| **S3 is not a database**               | Do not use S3 for high-frequency read/write of small objects. Use DynamoDB or a database instead.                                                                                             |
| **Bucket policy size limit**           | Max 20 KB. Complex policies can hit this limit. Use S3 Access Points for large-scale multi-tenant access control.                                                                             |
