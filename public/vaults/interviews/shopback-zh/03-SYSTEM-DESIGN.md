# 第三轮：领域知识评估 - 系统设计

## 形式

- **时长**：1 小时，HackerRank
- **方式**：与面试官开放式系统设计讨论
- **工具**：HackerRank 的绘图/文本环境
- **重点**：架构、权衡、ShopBack 规模下的扩展性

## 四步框架

### 第一步：需求澄清（5-8 分钟）

- **功能性需求**：系统做什么？
- **非功能性需求**：规模、延迟、可用性、一致性
- **约束**：预算、团队规模、现有基础设施
- **不在范围内**：我们不构建什么？

### 第二步：高层设计（10-15 分钟）

- 绘制架构图
- 识别核心组件及其交互
- 定义 API 接口
- 选择数据存储策略

### 第三步：深入探讨（20-25 分钟）

- 详细阐述最关键的组件
- 讨论数据模型和表结构
- 解决扩展瓶颈
- 处理故障模式

### 第四步：权衡与扩展（5-10 分钟）

- 讨论你考虑过的替代方案
- 规模扩大 10 倍后会有什么变化？
- 监控和可观测性
- 未来改进方向

## 历年系统设计题目

### 1. "设计前端和后端的高效部署方案"

这是关于 **CI/CD 和部署架构**的题目。参见下方框架。

### 2. "给定白板上的一个设计，进行评审和改进"

测试你评估现有系统的能力。练习发现：

- 单点故障
- 瓶颈
- 缺失的缓存层
- 不完善的错误处理
- 安全漏洞

### 3. "处理消息队列中的阻塞消息"

这是 ShopBack 中**真实的运维问题**。关键解决方案：

- 死信队列（DLQ）
- 消息 TTL 和重试策略
- 熔断器
- 监控和告警
- 手动重放机制

### 4. "设计基于会话的认证系统"

涵盖认证基础。考虑：

- 会话存储（Redis、数据库）
- Token 与 Session 的权衡
- 13 个市场的跨域认证
- 会话失效策略

## 快速参考：事件驱动架构

ShopBack 大量使用事件驱动架构。准备讨论：

```
┌─────────┐     ┌──────────────┐     ┌──────────────┐
│ 点击    │────→│ 事件总线     │────→│ 归因         │
│ 服务    │     │ (Kafka/SQS)  │     │ 服务         │
└─────────┘     └──────┬───────┘     └──────────────┘
                       │
                ┌──────┴───────┐
                │              │
         ┌──────┴──┐    ┌─────┴──────┐
         │分析    │    │通知        │
         │服务    │    │服务        │
         └─────────┘    └────────────┘
```

### 核心概念

- **事件溯源**：将事件作为事实来源存储，由事件推导状态
- **CQRS**：读写模型分离，满足不同的扩展需求
- **Saga 模式**：协调多服务事务（点击 → 购买 → 返现）
- **死信队列**：处理失败的事件处理
- **幂等性**：确保重复事件不会导致重复返现

## 快速参考：部署与 CI/CD 设计

这是历年真题之一：

```
┌──────────┐    ┌────────┐    ┌───────────┐    ┌───────────┐
│ Git Push │───→│ CI/CD  │───→│  金丝雀   │───→│  全量     │
│          │    │ 流水线 │    │  部署     │    │  发布     │
└──────────┘    └────────┘    └───────────┘    └───────────┘
                    │              │
                    ▼              ▼
               ┌────────┐    ┌───────────┐
               │ 测试   │    │ 指标      │
               │ 检查   │    │ 监控      │
               │ 构建   │    │ 告警      │
               └────────┘    └───────────┘
```

### ShopBack 相关要点

- **多区域部署**：5 个 AWS 区域，13 个市场
- **金丝雀策略**：将 1-5% 的流量路由到新版本，监控错误
- **功能开关**：无需重新部署即可按市场启用功能
- **回滚**：错误率激增时自动回滚
- **蓝绿部署**：关键服务零停机部署

## 系统设计沟通技巧

1. **从需求开始** - 不要直接跳到架构
2. **边说边画** - 可视化沟通很关键
3. **明确假设** - "我假设我们需要处理每天 50 万笔交易"
4. **讨论权衡** - "我们可以用 X 或 Y。X 在一致性方面更好，Y 在延迟方面更好"
5. **引用 ShopBack** - "鉴于 ShopBack 的多市场模式，我会考虑…"
6. **保持诚实** - 如果不知道某些东西，就说出来并推理
7. **考虑故障** - "当这个服务挂掉时会发生什么？"
