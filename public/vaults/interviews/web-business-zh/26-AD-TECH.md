# 广告与广告技术

## 这是什么？

广告技术（Ad Tech）是支撑互联网广告投放、交易和优化的整个技术生态系统。它解决的核心问题是：广告主想在正确的时间、正确的地方、向正确的人展示广告，而发布商（网站/App）想把自己的流量变现。Ad Tech 就是连接这两端的技术中间层——包括广告交易平台、竞价系统、定向引擎、归因追踪等。作为开发者，你可能需要接入广告 SDK、搭建广告投放后台、实现竞价逻辑，或者处理广告数据的采集和分析。

## 为什么要懂？

广告是互联网最大的商业模式之一。Google 和 Meta 的绝大部分收入来自广告。即使你不在广告公司工作，你也几乎一定会遇到广告相关的需求：在网站上接入 Google Ads、实现广告位管理、追踪广告转化、或者优化广告投放的 ROAS。更重要的是，广告技术涉及实时竞价、大规模数据处理、隐私合规等复杂技术挑战——理解这些能让你在面试和实际工作中脱颖而出。

## 业务流程

### 广告生态系统的角色

整个广告生态有四个核心角色：

```
广告主（Advertiser）        发布商（Publisher）
   想投广告的公司               有流量的网站/App
        ↓                           ↓
   DSP（需求方平台）          SSP（供给方平台）
   帮广告主买广告位            帮发布商卖广告位
        ↓                           ↓
        └─────── Ad Exchange ────────┘
                 广告交易所
                 撮合买卖双方
                    ↑
                   DMP
              数据管理平台
           提供用户画像数据
```

- **广告主（Advertiser）**：想推广产品或服务的公司，比如 Nike、Airbnb
- **发布商（Publisher）**：拥有用户流量的网站或 App，比如新闻网站、博客
- **广告网络（Ad Network）**：聚合多个发布商的广告位，打包卖给广告主
- **DSP（Demand-Side Platform）**：广告主用来自动化购买广告位的平台
- **SSP（Supply-Side Platform）**：发布商用来自动化售卖广告位的平台
- **DMP（Data Management Platform）**：收集和整合用户数据，提供定向投放依据
- **Ad Exchange**：连接 DSP 和 SSP 的实时交易市场

### 计价模式

广告的收费方式有几种主流模式：

| 模式 | 全称             | 含义                       | 典型场景           |
| ---- | ---------------- | -------------------------- | ------------------ |
| CPM  | Cost Per Mille   | 每千次展示付费             | 品牌曝光广告       |
| CPC  | Cost Per Click   | 每次点击付费               | 搜索广告、效果广告 |
| CPA  | Cost Per Action  | 每次转化付费（注册、购买） | 效果导向广告       |
| CPV  | Cost Per View    | 每次观看付费               | 视频广告           |
| CPI  | Cost Per Install | 每次安装付费               | 移动 App 推广      |

广告主偏好 CPA（只为结果付费），发布商偏好 CPM（只要展示就有钱）。实际选择取决于双方的议价能力和广告类型。

### 实时竞价（RTB）与程序化广告

程序化广告是用自动化系统替代人工谈判来买卖广告位。RTB 是其中最常见的方式：

```
1. 用户打开一个网页
2. 网页向 SSP 发出广告请求（带上用户信息：设备、地理位置、Cookie 等）
3. SSP 把请求转发到 Ad Exchange
4. Ad Exchange 向所有接入的 DSP 发起竞价请求（Bid Request）
5. 各 DSP 根据广告主的预算、定向条件、出价策略，在约 100ms 内返回出价
6. Ad Exchange 选出最高出价的 DSP（通常是第二高价拍卖）
7. 获胜的广告素材展示给用户

整个过程在 200ms 内完成——用户几乎感觉不到延迟。
```

### 定向投放

广告的价值在于精准。常见的定向方式：

- **人口统计定向**：按年龄、性别、收入水平、教育程度投放
- **地理定向**：按国家、城市、甚至 GPS 坐标投放
- **行为定向**：根据用户的浏览历史、购买记录、兴趣标签投放
- **上下文定向**：根据当前页面的内容投放（体育新闻页面投放运动品牌广告）
- **再营销（Retargeting）**：用户浏览了你的商品但没买，之后在别的网站上看到你的广告

再营销是转化率最高的定向方式之一，因为用户已经表现出了兴趣。

### 归因模型

用户看了多个广告，最后下单了——哪个广告应该得到功劳？这就是归因问题。

| 归因模型                | 逻辑                                 | 优缺点                   |
| ----------------------- | ------------------------------------ | ------------------------ |
| 首次触达（First Touch） | 第一个接触到用户的广告得到全部功劳   | 简单，但忽略了后续影响   |
| 末次触达（Last Touch）  | 最后一个接触到用户的广告得到全部功劳 | 最常用，但忽略了前期铺垫 |
| 线性归因（Linear）      | 所有接触点平均分配功劳               | 公平，但没有区分重要性   |
| 时间衰减（Time Decay）  | 越接近转化的接触点功劳越大           | 比较合理，但配置复杂     |
| 数据驱动（Data-Driven） | 用机器学习计算各触点的实际贡献       | 最准确，但需要大量数据   |

### 广告活动管理

一个典型的广告活动（Campaign）结构：

```
广告活动（Campaign）
├── 目标：提升 App 下载量
├── 预算：每日 ¥5000
├── 时间：2026-03-01 至 2026-03-31
│
├── 广告组 1（Ad Group）——定向 18-25 岁用户
│   ├── 广告素材 A（图片 + 文案版本 1）
│   └── 广告素材 B（图片 + 文案版本 2）
│
└── 广告组 2（Ad Group）——再营销用户
    ├── 广告素材 C（视频版本）
    └── 广告素材 D（轮播图版本）
```

通过对比不同广告组和素材的表现，找到最佳组合——这就是广告 A/B 测试。

### 广告欺诈检测

广告欺诈每年造成数百亿美元的损失。常见的欺诈类型：

- **点击欺诈（Click Fraud）**：用脚本或雇人大量点击 CPC 广告，消耗竞争对手预算
- **展示欺诈（Impression Fraud）**：把广告塞到 1x1 像素的 iframe 里，用户根本看不到但算展示
- **机器人流量（Bot Traffic）**：用自动化程序模拟真实用户浏览和点击
- **广告堆叠（Ad Stacking）**：在同一个位置叠放多个广告，只有顶层可见但全部计费
- **域名欺骗（Domain Spoofing）**：低质量网站伪装成高流量网站来骗取高价广告

检测方法包括：分析点击频率异常、检查 IP 地址和设备指纹、验证可见性（Viewability）、使用 ads.txt 验证授权卖方。

## 常见术语

| 术语                   | 解释                                                                |
| ---------------------- | ------------------------------------------------------------------- |
| **CPM**                | 每千次展示成本（Cost Per Mille）                                    |
| **CPC**                | 每次点击成本（Cost Per Click）                                      |
| **CPA**                | 每次行动成本（Cost Per Action）                                     |
| **CTR**                | 点击率 = 点击数 / 展示数 × 100%                                     |
| **CVR**                | 转化率 = 转化数 / 点击数 × 100%                                     |
| **ROAS**               | 广告支出回报率 = 广告带来的收入 / 广告花费                          |
| **ROI**                | 投资回报率 = (收入 - 成本) / 成本 × 100%                            |
| **DSP**                | 需求方平台，广告主用来买广告位                                      |
| **SSP**                | 供给方平台，发布商用来卖广告位                                      |
| **DMP**                | 数据管理平台，存储和分析用户画像数据                                |
| **RTB**                | 实时竞价（Real-Time Bidding）                                       |
| **Fill Rate**          | 填充率 = 实际展示广告的请求数 / 总广告请求数                        |
| **eCPM**               | 有效千次展示收入，统一不同计价模式的比较基准                        |
| **Frequency Cap**      | 频次上限，限制同一用户看到同一广告的次数                            |
| **Viewability**        | 可见性——广告是否真的被用户看到了（IAB 标准：50% 面积可见超过 1 秒） |
| **Ad Inventory**       | 广告库存，发布商可供出售的广告位总量                                |
| **Retargeting**        | 再营销，对已访问过的用户再次投放广告                                |
| **Lookalike Audience** | 相似受众，基于现有高价值用户特征找到类似的新用户                    |

## 常见模式

### 模式一：瀑布竞价（Waterfall）

发布商按优先级逐个询问广告网络，第一个愿意出价的就赢。

**适用场景：** 早期广告变现、接入广告网络数量少。

**取舍：** 简单但效率低。排在后面的广告网络可能出价更高却没机会竞价。

### 模式二：头部竞价（Header Bidding）

所有广告网络同时收到竞价请求，出价最高的赢。

**适用场景：** 大型发布商希望最大化广告收入。

**取舍：** 收入提升 20-50%，但增加了页面加载延迟（额外 200-500ms）。需要仔细优化超时设置。

### 模式三：服务端竞价（Server-Side Bidding）

把竞价逻辑从浏览器移到服务端，减少客户端性能影响。

**适用场景：** 对页面性能要求高的发布商。

**取舍：** 解决了延迟问题，但服务端看不到用户的 Cookie，定向精度可能下降。

### 模式四：自有广告平台

大型公司自建广告系统（如电商平台的站内广告）。

**适用场景：** 拥有大量第一方数据和流量的平台。

**取舍：** 完全控制广告体验和数据，但开发和维护成本极高。

## 踩坑提醒

- **隐私合规是硬性要求**：第三方 Cookie 即将被废弃，Apple 的 ATT 框架让 IDFA 获取率从 70% 暴跌到 25%。广告定向正在从依赖第三方数据转向第一方数据和上下文定向。不了解这些变化，你搭建的广告系统很快就会过时。
- **ROAS 不等于利润**：ROAS 为 3（花 1 元赚 3 元）看起来不错，但如果产品成本是 2.5 元，实际利润只有 0.5 元。永远要结合毛利率看 ROAS。
- **归因窗口很关键**：同样的广告活动，7 天归因窗口和 30 天归因窗口的 CPA 可能差 2-3 倍。比较数据时务必确认归因窗口一致。
- **广告疲劳**：同一个用户反复看到同一条广告，CTR 会急剧下降甚至产生反感。设置 Frequency Cap 并定期更换素材。
- **不要忽略广告欺诈**：尤其是 CPC 和 CPI 模式下，欺诈流量可能占 20-30%。接入 IVT（无效流量）检测工具是必须的。
- **A/B 测试要控制变量**：同时改文案、图片和定向条件，你无法知道到底是什么起了作用。每次只改一个变量。
